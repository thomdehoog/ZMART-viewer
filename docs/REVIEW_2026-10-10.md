# Review of the ZMART Viewer, 10 October 2026

This is a code review of the ZMART Viewer as it stood on `main` at commit
`d13378f` (version `0.5.0rc1`). It was written by Claude at Thom's request and
follows the order that `REVIEW_PROMPT.md` asks for. ZMART-interface was
reviewed on the same day; its report is `docs/REVIEW_2026-10-10.md` in that
repository.

**How to read it.** Every finding gives the file and line, what is wrong, a
situation in which it goes wrong, and a fix. *Confirmed* means the code path
was traced or the fault was reproduced; *plausible* means it is believed but
was not fully traced or run.

**What the review did and did not do.** The code was read and the tests were
run on Linux, in a copy of the repository. Nothing was tested on Windows:
every finding about Windows comes from reading the code or from imitating the
error on Linux. The clone had no history, so the tree was reviewed as it
stands and not as a difference from `6791d28`. About 310 of the browser tests
were not run. Section 8 names the files that were not read; no conclusion
should be drawn about those.

## 1. Verdict

**Ready to release after fixes.** Every test that ran passed, the wheel holds
what it should, and the committed page rebuilds byte for byte. Four things
should be fixed first. The three biggest issues are:

1. **The HTTP server trusts any caller.** It accepts any `Host` and `Origin`
   and reads JSON from any content type, so a web page open in the same
   browser can open folders, close what is on screen and overwrite the file of
   marked places. It also serves the whole parent folder of an opened image.
2. **Two ways in which a live picture goes black or stale.** One failed read
   of `signed.json` empties the picture and deletes its baked overview until
   the next commit. Position names that contain a dot leave the baked overview
   stale for good after a restart.
3. **The standalone promise fails in two common cases.** An image whose name
   has a space or an umlaut cannot be drawn. A folder of positions opened by
   its path is frozen at the moment of opening, while the guide says new
   positions appear within a second.

## 2. Must fix before release

### M1. One failed read of `signed.json` blanks the live picture and deletes its baked overview (mechanism confirmed; the trigger on Windows is plausible)

- **Where:** `engine/live/record/live_serving.py:157`, through
  `manifest.py:623` and `manifest.py:396-421`.
- **What is wrong:** `_published_units()` calls `manifest.events()`, which
  reads the marker through the forgiving `committed()`. A marker that cannot
  be read becomes "revision 0", the running total is reset to "nothing
  published", and that empty answer is remembered.
- **How it goes wrong:** a commit lands, and one read of `signed.json` fails
  (a brief hold during `os.replace`, or a virus scanner). Imitating exactly
  one failed read: before it, the piece decodes and three baked files exist;
  after it, the piece is `None` and no baked file remains, on every later
  request until another commit arrives.
- **Fix:** `events_through()` exists for this, and `LiveStateTracker.observe`
  already handles the same danger.

```diff
-                events = self.manifest.events()
+                events = self.manifest.events_through(self.manifest.committed_strict())
```

  With this change the same imitation answers "try again shortly" once and
  then serves correctly; 70 related tests pass.

### M2. Position names that contain a dot leave the baked overview stale after a restart (confirmed, reproduced)

- **Where:** `engine/picture/built_picture.py:1267-1271`,
  `engine/picture/arrangement.py:1129`.
- **What is wrong:** `tile.name.split(".")[0]` is used to get the position's
  name from a folder name. `vocabulary.py:136` allows dots in names and only
  reserves the ending `.generation-N`.
- **How it goes wrong:** positions `pos.A` and `pos.B`; bake; stop the viewer;
  `pos.B` lands; start again. The catch-up finds no tile called `pos` among
  what it missed, repairs nothing, and marks the bake as up to date. The
  pieces `3/c/0/0/0`, `3/c/0/0/1` and `4/c/0/0/0` then differ from a fresh
  bake; with `posA` and `posB` they match. Zoomed out, the position is missing
  for good.
- **Fix:** remove only the generation ending, in both places.

```python
# arrangement.py
_A_GENERATION_SUFFIX = re.compile(r"\.generation-\d+$")
def the_position_of(tile_name: str) -> str:
    return _A_GENERATION_SUFFIX.sub("", tile_name)
```

  Checked: with this change the repaired bake equals a fresh one.

### M3. The HTTP server checks no Host, Origin or content type (confirmed, reproduced)

- **Where:** `engine/serving/server.py:291-328` (routing), `897-956`
  (`_serve_api_post`), `1166-1232` (`_serve_open`).
- **What is wrong:** every request is served whatever its `Host` and `Origin`.
  The body of a POST is read as JSON without `Content-Type: application/json`,
  so a form-style POST from another site needs no preflight.
- **How it goes wrong** (with `Host: attacker.example:8848`,
  `Origin: http://attacker.example` and `Content-Type: text/plain`):
  - `POST /api/stores/open` answers 200, even with `allow_open=False`; the
    files in that folder can then be read under `/data/1/`.
  - `POST /api/annotations` answers 200 and `zmart-annotations.json` is
    written. The guide says the software that runs the experiment acts on
    that file.
  - `POST /api/stores/close` answers 200.
  - `GET /data/0/secret.txt` with the foreign `Host` answers 200. That is the
    reading half of a DNS-rebinding attack, made easier by the fixed default
    port 8848.
- **What holds:** the server listens on `127.0.0.1` only (`server.py:1850`).
  Leaving the open folder is refused (`/data/1/../../…` answers 403,
  `%2e%2e` answers 404). The annotation document is checked and limited in
  size.
- **Fix:** in `do_GET`, `do_POST` and `do_HEAD`, answer 403 unless `Host` is
  `127.0.0.1`, `localhost` or `[::1]`, and unless `Origin`, when present, is
  one of those or is in a new list `make_server(allowed_origins=…)`. For a
  POST with a body, require `application/json`. The page already sends that
  header everywhere except the body-less `/api/browse`.
- **A decision for you:** `allow_open=False` guards only `list` and
  `construct*`, not `/api/stores/open` or `close`. The ZMART interface calls
  `/api/stores/open` (with `allow_open=True`), so check it before guarding
  them. The interface also adds `Access-Control-Allow-Origin: *` to every
  answer by replacing methods on the handler class
  (`parts/storage/viewer_service.py:655-687` there); `allowed_origins=` would
  make that unnecessary.

### M4. Images whose names need percent-encoding cannot be drawn (confirmed at the server)

- **Where:** `engine/serving/server.py:369`; addresses are built at
  `server.py:1522`, `1582`, `engine/live/following.py:367` and
  `engine/serving/coverage.py:26`.
- **What is wrong:** the `/data/` path is never percent-decoded, and the
  addresses in `/api/config` are never encoded.
- **How it goes wrong:** `my image.ome.zarr` is asked for as
  `/data/1/my%20image.ome.zarr/zarr.json` and answers 404.
  `Überblick.ome.zarr` answers 404. For `a#b.ome.zarr` the browser cuts the
  address at `#`, and it answers 404. Only the name inside the opened folder
  matters; parent folders with spaces are fine.
- **Fix:** both halves together. Write `quote(name, safe="/")` wherever a
  `/data/…` address is built, and `unquote()` the path in `_serve_from_data`
  and in `_serve_measurement` (`server.py:790`). `Library.resolve` runs after
  the decoding, so the guard against leaving the folder keeps working.

## 3. Should fix

### S1. Opening one image serves its whole parent folder (confirmed)

`engine/opening/open_folders.py:695-700`, `1216-1222`. `discover()` returns
`path.parent` as the root and `resolve()` allows anything beneath it.
`GET /data/0/secret.txt` returned the content of a file beside the image.
Opening `~/image.ome.zarr` exposes all of the home folder. **Fix:** for an
image opened by name, allow only paths under one of its stores or its
borrowed folders; keep the whole-root rule for run roots, which need `data/…`
and `views/…`.

### S2. A folder of positions opened by path is frozen; a plate writes beside the data; a failed write gives no answer (confirmed)

`engine/opening/open_a_path.py:91-100` and `101-137`;
`engine/serving/server.py:1204-1214`; `gui/source/LoadWindow.jsx:65-68`.

- **Frozen picture:** `scene_behind_a_run` composes a fixed picture, and the
  library then watches the session's scene folder and not the data. Three
  positions were opened and a fourth landed; four seconds later `/api/config`
  still listed the one picture, and its description still said three tiles.
  `docs/README.md:50` says "New positions appear within a second", and the
  root README shows `zmart-viewer /path/to/run` as the way to watch a run.
- **Plate:** opening `plate.ome.zarr` created `scenes/` in the plate's parent
  folder. `docs/README.md:116` says "nothing is written beside your data".
- **No answer:** when that folder cannot be created, the `OSError` escapes
  (`_serve_open` catches only `CannotOpen`) and the connection is dropped. In
  the page, `openStore` has no `try/finally`, so the load window stays busy.
- **Fix:** put plate scenes in the session folder, as run scenes already are.
  For a watched folder, either declare the scene again when `discover()` finds
  a new position, or do not compose while live. Catch `OSError` in
  `_serve_open` and answer with JSON. Wrap `openStore` in `try/finally`.

### S3. The end of a publication does not wait out a brief hold (mechanism confirmed by imitation; the trigger on Windows is plausible)

`engine/views/publishing.py:1275-1279`, also `:1431`;
`engine/views/projections.py:183-196`.

- **What is wrong:** `pending.json` is removed with a bare `.unlink()` after
  `publication.json` is in place and before the state in memory moves on.
- **How it goes wrong:** the unlink is refused once. Then the revision on disk
  is 2, the server reports 1, no page is told, `pending.json` stays, and the
  rewritten pieces answer 503 until another announcement repairs it.
- **Fix:**

```diff
         put_json_in_place(self._shown / "publication.json", state)
-        (self._shown / "pending.json").unlink()
         self._state = state
         self._state_mark = (self._shown / "publication.json").stat().st_mtime_ns
         self._held = made
         if previous is not None:
             previous.stop_warming()
+        done_despite_brief_holds(os.unlink, self._shown / "pending.json")
```

  Use `rmtree_despite_brief_holds` at `:1431` and in `projections.py`. The
  docstring of `write_projection` says "renamed into place in one step", but
  replacing an existing product takes two renames, with a moment in which the
  product is absent.

### S4. A failed read of an image's description is remembered (confirmed, with an equal timestamp)

`engine/opening/open_folders.py:218-250` and `263-280`. The memory is keyed on
`st_mtime_ns` alone, and a JSON error is remembered as `{}`. A half-written
`zarr.json` that is read once and then completed within the same timestamp
stays "not an image" for ever. File systems with coarse timestamps make this
realistic for the one-second watcher; `server.py:656` and
`shard_lookup.py:451` already guard against the same thing. **Fix:** key on
`(st_mtime_ns, st_size)` and do not remember a failed read.

### S5. `/api/config` hands out coverage addresses that the server refuses (confirmed)

`engine/serving/server.py:375-381` against `1691-1712`. For a published
acquisition without a named view and with the default
`transparent_background=False`, the row carries `coverageSources`, but
`GET …/.zmart-viewer/stack.ome.zarr/__zmart_coverage__/zarr.json` answers 403
(200 with `transparent_background=True`, which is the only case the tests
cover). **Fix:** also allow the marker when the store's `zmart` attributes
carry `published_from`.

### S6. Files without a hash in their name, and 404 answers, are served as "immutable" for a year (confirmed)

`engine/serving/server.py:278-287`. `/async_computation.bundle.js` (a 1.6 MB
worker with a fixed name), `/build-manifest.json` and a 404 for
`/no-such-file.js` all carry `public, max-age=31536000, immutable`. After an
upgrade, a browser on the same address keeps the old worker beside the new
page. The same applies to an interface's own `site_dir` files. **Fix:**

```python
hashed = code == HTTPStatus.OK and self.path.startswith("/assets/")
self.send_header("Cache-Control", "no-store" if page else
                 "public, max-age=31536000, immutable" if hashed else "no-cache")
```

### S7. Files put in place can be read only by their owner on Linux and macOS (confirmed)

`engine/filesystem.py:161-168`. `NamedTemporaryFile` creates the file with
mode 0600 and the rename keeps it: an ordinary write gave `0o644`,
`put_text_in_place` gave `0o600`. This affects `zarr.json`, `signed.json`,
`publication.json` and the annotations file, so another account on a shared
server cannot read the run. **Fix:** create the temporary file with
`os.open(…, O_CREAT | O_EXCL, 0o666)`, or copy the destination's mode before
the rename.

### S8. The thread that watches the manifest stops on one error (plausible)

`engine/live/following.py:250-253`. `_watch` calls `check_once()` without a
guard. `check_once` reaches `live_run_holding`, which uses `Path.resolve()`
and `is_dir()`; these raise on a network-share error. `FolderWatcher` guards
exactly this (`:172`). After the thread stops, commits reach pages only
through the slower `/api/live-state` check. **Fix:** wrap `check_once()` in
`try/except Exception` with a line in the log.

### S9. A built picture labels any unit as micrometres (confirmed by reading)

`engine/picture/arrangement.py:429-449` reads scale and translation without
the axis unit; `:1944-1946` always writes `"unit": "micrometer"`. Positions or
a plate declared in nanometres or millimetres get a scale bar that is wrong by
a factor of 1000. `write_projection` refuses input that is not in micrometres
(`projections.py:135`). **Fix:** read the unit in `read_one_tile` and convert
or refuse.

### S10. The remembered `/api/config` answer can be half-replaced (confirmed by reading; depends on timing)

`engine/serving/server.py:1432-1449`. The check without a lock reads
`["revision"]` and then `["config"]`, and the writer sets them in that order.
A request in between gets the old answer under the new revision, or `null` on
the very first build. If that was the last announcement of a run, the page
stays one step behind. **Fix:** keep one pair
`self._last_built = (revision, built)` and read it once.

### S11. Packaging details

- `pyproject.toml:2` asks for `setuptools>=70.1`, but `license = "MIT"` with
  `license-files` needs 77 or newer. The dev extra already says so. **Fix:**
  `requires = ["setuptools>=77"]`.
- `requires-python = ">=3.11,<3.13"` leaves out current Pythons. On 3.13 with
  `--ignore-requires-python` the package installs, imports and runs
  `zmart-viewer --help`; the tests were not run there.
- `pywebview>=5` is always required, although only `gui/window.py` uses it and
  already copes without it. An extra `[window]` would spare installs that need
  only the engine.
- `numpy>=1.24` and `zarr>=3,<4` are loose. `Composer.__init__`
  (`arrangement.py:1031-1048`) refuses to start if zarr's default codecs ever
  change. Tested here with zarr 3.4.1 and numpy 2.5.3.

### S12. The split between engine and GUI

**In `engine/` only for the standalone window:**

- `ask_this_machine_for_a_folder` (tkinter) in
  `engine/serving/server.py:1354-1372`; only `gui/window.py:99` calls it.
- `serve()` and the `__main__` block at `server.py:1869-1888`, and the
  `main()` command in `engine/picture/built_picture.py:359-395`.
- `make_server(chrome=, panel_side=, allow_selection=, depth_samples=)` and
  the config keys `chrome`, `panelSide`, `canSelect` and `depthSamples`. These
  are settings of the window's page, carried in the engine's public function.
- `/api/browse`, `/api/stores/list`, `/api/stores/construct*` and
  `/api/annotations` serve the load window and the selection list.
- `gui/window.py:25` imports the private `_FRONTEND_DIST`.

**In `gui/` that an embedding interface needs:**

- `gui/source/drawing/neuroglancer.js`, `layers.js`, `live-refresh.js` and
  `viewer.js`. They hold the handing-over of stores in groups (the fix for
  positions silently missing above about 680), the axis order that keeps the
  picture from being mirrored, the refresh on a new revision, and the
  first-zoom fix.
- `gui/source/scripts/patch_neuroglancer.mjs`. Its header says the interface
  keeps a copy, aligned by hand, in
  `application/patches/neuroglancer+2.41.2.patch` of ZMART-microscopy; that
  copy now lives in `patches/` of ZMART-interface. `embedding.js` relies on
  these patches for a refresh without a black frame, but only the growth patch
  is shared.

**Proposal:** yes, offer them ready-built. Move all three patch tables into
`engine/drawing/` beside `neuroglancer-growth.mjs`. Add a Vite library build
that makes one `drawing.js` (neuroglancer, the two workers, `syncLayers`,
`keepSpatialAxes` and the rest), served beside `/embedding.js` under the same
`EMBEDDING_API_VERSION`.

## 4. Nice to have

- **N1. Reading requests** (`server.py:929-935`, `557-567`, `836`): a
  `Content-Length` that is not a number drops the connection (reproduced); a
  negative one blocks the thread; invalid UTF-8 escapes the `JSONDecodeError`
  catch. `_send_bytes` writes a body for `HEAD`. `HEAD /embedding.js` answers
  404. A `RuntimeError` from a publication escapes `_serve_announcement`.
- **N2. Stop removes an older scene** (`server.py:1138-1143`): cancelling a
  build runs `rmtree` on the whole scene folder, including one that existed
  before. `built_picture.py:119` does `int(kept.name)` on anything that
  matches `[0-9]*`.
- **N3. Session folders pile up** (`server.py:1154-1164`, `1745-1755`):
  `~/.zmart-viewer/scenes/session-*` is removed only in `shutdown()`. A viewer
  that was killed left one behind. Clear old ones at start.
- **N4. Small races:** `open_folders.py:490-492` goes through three shared
  dictionaries while request threads add to them. `picture_pieces.py:1039`
  removes the per-store lock while another thread may hold it.
  `PublishedAcquisition.publish` has no lock of its own.
- **N5. Cost for the writer:** `publisher.py:655-659` uses `not in` on a list,
  which grows with the square of the number of positions on each publish.
  `signed.json` carries every position and is rewritten, and pushed to disk,
  on every commit. For the reader, `live_serving.py:96` sorts all position
  names on each chunk request.
- **N6. Relinking on Windows** (`gui/source/LoadWindow.jsx:76`):
  `path.slice(0, path.lastIndexOf("/"))` on a path with only backslashes drops
  its last character. Line 308 notes that the same mistake was fixed elsewhere.
- **N7. Memory is limited per picture, not per process:** 1 GiB of blocks plus
  256 MiB of slabs for each open picture (`arrangement.py:866-868`), and up to
  200,000 array descriptions (`shard_lookup.py:523`).
- **N8. `shutdown()` before `serve_forever()` hangs** (this is the standard
  library's behaviour, which `_Server.shutdown` inherits).
  `docs/view_modes.md:215-219` shows `server_close()` alone, which stops
  neither the watchers nor the published views.
- **N9. The build check's message** (`build_support.py:36-45`): it caught
  every stale case tried, but it never names the offending file, so a stray
  `.DS_Store` reads as "Run npm run build". The refactor report lost a test
  run to exactly that.
- **N10. Step 2 of `REFACTOR_REPORT.md` is not accurate.** Private names are
  still imported across modules: `_LiveRun` (`following.py:289`, `:545`,
  `built_picture.py:28`), `_the_description_of` (`open_a_path.py:75`),
  `_FRONTEND_DIST` (`gui/window.py:25`), and attribute reach-ins such as
  `pieces._composer_for` and `governed._run._geometry()`.
- **N11. Automatic checks:** `.github/workflows/tests.yml` runs the browser
  tests only by hand, so about a third of the tests never run automatically.
  It triggers on a branch `release-candidate`, which is not the name the brief
  gives.

## 9. What is good

- The way a commit is made is sound: the history line first, then one rename
  of `signed.json`, a strict tracker, and a recovery path that keeps the
  evidence.
- `PublishedTransfer.composer()` keeps serving the previous generation without
  waiting, and `pending.json` names exactly the pieces to hold back.
- `shard_lookup.py` checks offsets, overlaps and checksums, limits its memory,
  and refuses to remember a file whose timestamp is still moving.
- The guard against leaving the open folder is one function
  (`Library.resolve`) used by every file route, and it held under every
  attempt.
- Building is limited (`_BUILDS_AT_ONCE`) and is given up when the browser has
  hung up.
- The wheel is exactly what it should be, and the build check works.
- Error messages say what happened and what to do, in plain words.
- The tests are many and they pass, and they refuse to pass quietly when no
  picture was looked at.

## 10. The embedding surface as it is in the code

This was written down to compare with what the ZMART interface expects; that
comparison is in the interface's review, under "Where the interface meets the
viewer". One difference was found: the interface sends `span` to
`/api/measure`, and nothing in the server appears to read it.

### Python

- `zmart_viewer.make_server(port=8848, *, data_dir=None, site_dir=<built page>, store=None, loads=None, window=None, depth_samples=256, chrome=False, browse=None, live=True, allow_open=True, allow_selection=False, panel_side="right", transparent_background=False, open_from=None, bake=False, canvas=None)`
  returns a `ThreadingHTTPServer` on 127.0.0.1 that has not been started.
- `PublishedAcquisition(folder, piece=512)`:
  `.publish(folder, versions, canvas, *, composition, bake=True)`, `.outputs`,
  `.sources`, `.revision`, `.bake`, `.close()`.
- `STORE = ".zmart-viewer/overview.ome.zarr"`.
- `write_projection(source, destination, method, *, regions="complete", revision=0, piece=256, xy_origin="center")`.

### HTTP routes (`engine/serving/server.py`)

| Method and path | What is sent | Answer |
|---|---|---|
| `GET /` and static files | nothing | Files from `site_dir` |
| `GET /embedding.js` | nothing | The module, with `Access-Control-Allow-Origin: *` and `no-cache`. `HEAD` answers 404 |
| `GET /api/health` | nothing | `{"ok": true}` |
| `GET /api/config` | nothing | See below |
| `GET /api/events` | nothing | Server-sent events: `: listening`; `event: changed` with `data: {}` or `data: {"imageWrittenInPlace": true}`; `: still here` every 15 s |
| `GET /api/live-state` | optionally `If-None-Match` | `{"schema": "zmart-live-frontend-state-set/1", "runs": [...]}` with an `ETag`, or 304 |
| `GET /api/annotations` | nothing | `{"version": 1, "annotations": [...]}`, or 500 with `{"error"}` |
| `GET`/`HEAD /data/<n>/<store>/<path>` | optionally one `Range`, `If-None-Match` | Bytes. 206 for a range, 304, 403 outside an open folder, 404 if absent or not yet published, 416, 503 "try again" |
| `GET /data/<n>/<store>/__zmart_coverage__/…` | nothing | A virtual uint8 zarr v3 group (gzip chunks); 403 unless there is a transparent background, a named view or a projection (see S5) |
| `POST /api/stores/open` | See below | 200 with the same body as `/api/config`; 400, 404, 409 (`relink`) or 503 with `{"error"}` |
| `POST /api/stores/close` | `{"group": "<panel label>"}` | 200 with the config |
| `POST /api/announce` | See below | `{"told": <listeners>}`; 400 or 503 with `{"error"}` |
| `POST /api/measure` | `{"sources": [url…]` or `"source": url, "box": [[top, left], [bottom, right]]` as fractions, `"channel"?: int}` | `{"window": {low, high}, "histogram": {low, high, counts[], autoWindow{low, high}}}` or `{"empty": true}` |
| `POST /api/annotations` | `{"version": 1, "annotations": [{"id", "type": "point" or "axis_aligned_bounding_box", "point" or "pointA"/"pointB": [1–8 numbers], "description"?: up to 1000 characters}]}`, at most 10,000 | The cleaned document; 400, 409 or 500. Writes `<data_dir>/zmart-annotations.json` |
| `POST /api/browse` | nothing | `{"path", "parent"}`, `{"cancelled": true}`, 501 or 500 |
| `POST /api/stores/list` (404 if `allow_open=False`) | `{"path"?}` | `{"path", "kind", "parent", "folders": [{"name", "kind": "view"/"plate"/"image"/"run"/null, "baked"?}]}` |
| `POST /api/stores/construct` (404 if `allow_open=False`) | `{"path", "viewer_folder", "bake"?, "name"?}` | `{"started": true}`; 400, 404 or 409 |
| `POST /api/stores/construct-status` (same condition) | `{}` | `{"state": "idle"/"running"/"done"/"cancelled"/"error", "fraction", "bake", "store"?, "error"?}` |
| `POST /api/stores/construct-cancel` (same condition) | `{}` | `{"stopping": bool}` |

Any other `/api/` path answers 404. `OPTIONS` answers 501.

**What `POST /api/stores/open` takes:** `{"path"}`, and optionally `"bake"`,
`"canvas": {"x_um": [lo, hi], "y_um": [lo, hi]}`,
`"source_revisions": {"<name>.ome.zarr": int}`, `"composition"`, and
`"views": {"path", "acquisition", "modes"?: ["slice", "top"], "projections"?: ["min", "max", "sum"], "projection_path"?}`.

**The keys of `composition`:** `regions` (`"complete"` or
`{name: [region…]}`) and `order` are required. Also allowed:
`pyramid_reduction`, `xy_origin`, `z_references`, `view`, `originals`,
`original_revisions`, `depth_placement`.

**What `POST /api/announce` takes:**
`{"publications": [{"path", "source_revisions", "composition"?}]}`, or a plain
hint `{}` or `{"wrote_image_in_place": true}`.

**The body of `/api/config`:**

- Top level: `layers`, `groups`, `depthSamples`, `chrome`,
  `transparentBackground`, `canOpen`, `canSelect`, `panelSide`, `live`, and
  `liveState` when a governed run is open.
- An image row: `kind`, `name`, `group`, `channelIndex`, `sources`
  (`"/data/<n>/<store>/|zarr2:"` or `zarr3:`), `frames`, `frameCounts`,
  `color`, `window`, `volumeWindow`, `histogram`, `range`.
- Optional on an image row: `view {acquisition, type, method?}`,
  `sourceRevisions`, `sourceGeometryRevisions`, `sourceDepths`,
  `acquiredCoverage`, `opaque`, `coverageSources`, `active`.
- Rows of a governed run add: `localPosition`, `sourceIds`,
  `committedTimeRanges`, `liveRunId`.
- Mask rows have `kind: "segmentation"`.
